# JuliaMag Plan 2: Grids Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Grids become project items in `JuliaMagCore`.
They import from Geosoft `.grd` (uncompressed and compressed), Surfer `.grd`, ER Mapper `.ers` and GeoTIFF, and export to Geosoft `.grd`, ER Mapper `.ers` and GeoTIFF.
The plan also closes the plan 1 follow-ups that must be done before the UI (plans 3 and 4) depends on the core.

**Architecture:** A grid is a folder with `grid.json` and one raw value file (`values.f32` or `values.f64`), like a line database channel.
Every grid reader fills the grid through one shared sink, block by block, so no reader loads a whole file.
GDAL (ArchGDAL.jl) reads and writes ER Mapper, GeoTIFF and Surfer.
Geosoft `.grd` has its own reader and writer, because GDAL does not read it.
Grid imports and exports run as jobs through the importer and exporter registries of plan 1.

**Tech Stack:** Julia 1.12, ArchGDAL.jl 0.10 (GDAL 3.13), CodecZlib.jl 0.7, EzXML.jl 1, plus the plan 1 stack (JSON3, StructTypes, Proj, Mmap, Test, Aqua, JET).

**Spec:** `docs/superpowers/specs/2026-10-28-juliamag-foundation-design.md` (sections 5.1, 5.4, 6.1, 6.2, 6.7, 7, 8.4, 8.5, 9.3 "Statistics pane", 13.3, 14).
Research: `docs/research/oasis-grid-and-image.md` (sections 1, 2.8, 2.10, 2.12, 4.4, 4.5) and `docs/research/geosoft-grd-format.md` (byte layout, side files and public test files of Geosoft `.grd`, checked on real files).
Follow-ups: `docs/superpowers/plans/2026-10-28-plan-1-followups.md`.

## Global Constraints

- Julia 1.12 or newer.
- `JuliaMagCore` must not depend on any UI or graphics package (spec 13.3, "Code layout").
- New dependencies: `ArchGDAL = "0.10"`, `CodecZlib = "0.7"` and `EzXML = "1"`, each added in the task that first uses it (ruling R1 of plan 1). They resolve together with `Proj = "1.9"` (checked on 2026-10-29: ArchGDAL 0.10.12, GDAL 3.13.3, Proj 1.9.0).
- A whole grid file is never loaded into memory at once (spec 6.2). Readers and writers move blocks of rows of at most `GRID_BLOCK_BYTES = 16 MiB`.
- Missing grid values are `NaN` inside JuliaMag. A file's dummy or nodata value becomes `NaN` on read, and `NaN` becomes the format's dummy value on write.
- Grid values are stored as `Float32` or `Float64` only. Integer files become `Float32` when every value fits exactly (8 and 16 bit), else `Float64`. The source element type is kept in `grid.json` (spec 5.4).
- Georeference inside JuliaMag is Geosoft's: `x0, y0` is the centre of the lower-left cell, `dx, dy` are the cell sizes, `rotation` is in degrees counter-clockwise about `(x0, y0)`. Row 1 is the row through `y0` (south when not rotated). Converters to and from corner-based formats live in one file (Task 3).
- A grid's coordinate system is a text code: `"EPSG:n"` when Proj can identify it, else the WKT text, or `""` when unknown (same rule as `PositionPair.crs`).
- Bad input never throws out of an importer, exporter or tool to the caller; it becomes a failed job with a plain message, or a warning (spec 6.2, 8.2).
- Imports and exports are jobs (plan 1 rulings R11, R12): an export marks its grid with `mark_reading!`; an edit of a grid refuses a busy grid with `ItemBusyError`.
- Every file is written to `path * ".tmp"` (or a temp folder) and renamed at the end; a failure or cancel leaves the target untouched.
- All paths inside a project are relative to the project folder (spec 5.1). Item ids are never reused (plan 1 ruling R7).
- Windows is the main platform: close every memory map of a file before it is renamed, cut or removed (plan 1 ruling R6).
- Text in messages, comments and docs: plain English, short sentences, never the em dash character.
- Lint (Aqua, JET) and all tests pass before each commit. Tests never use the network.

## Review Focus

These inputs are not named by the spec but will reach real users first.
Each has a test in the task that owns the code.

1. **Orientation:** a grid with a known value in one corner keeps that value at the same ground position after import and export through every format, also when rotated, stored bottom-up or top-down, or stored by columns (Geosoft `KX = -1`) (Tasks 3, 4, 7, 8, 10).
2. **Broken and cut files:** a header that is fine but data that is short, a compressed block that is damaged, or an `.ers` whose data file is missing gives a failed job with a plain message, no new item and no temp folder left (Tasks 2, 4, 5, 6).
3. **Large grids:** a 1.6 GB grid (20,000 by 20,000 `Float32`) imports and exports with flat memory (Task 10).
4. **Dummies and scaling:** integer grids with `ZBASE` and `ZMULT` or GDAL scale and offset give the right real values, and every dummy or nodata cell becomes `NaN`; an all-dummy grid imports with no error (Tasks 3, 4).
5. **The wrong `.grd`:** a Surfer grid named `.grd`, or a file that is neither, gives a clear message that names the format found; a Geosoft grid with no side files imports with an empty coordinate system and a warning (Task 6).

### Task 1: Grid storage

**Files:**
- Create: `src/storage/grid.jl`, `test/test_grid.jl`, `test/support/grids.jl`
- Modify: `src/project/project.jl` (add `grid`), `src/JuliaMagCore.jl`, `test/runtests.jl`

**Interfaces:**
- Consumes: plan 1 `write_json_atomic`, `Project`, `item`, `item_path`, `item_missing`.
- Produces (spec 5.4):
  - `struct GridError <: Exception; msg::String; end`
  - `mutable struct GridStyle; colours::String; method::Symbol; min::Float64; max::Float64; reverse::Bool; shade::Bool; azimuth::Float64; altitude::Float64; zfactor::Float64; end`
    `GridStyle()` gives `("rainbow", :histeq, NaN, NaN, false, false, 45.0, 45.0, 1.0)`.
    `method` is one of `:linear`, `:histeq`, `:normal`, `:loglinear`; `NaN` limits mean "from the data".
  - `mutable struct GridSource; file::String; format::String; eltype::String; compression::String; end` (`GridSource()` is all `""`).
  - `mutable struct Grid; folder::String; name::String; eltype::DataType; nx::Int; ny::Int; dx::Float64; dy::Float64; x0::Float64; y0::Float64; rotation::Float64; crs::String; units::String; source::GridSource; trend::Vector{Float64}; style::GridStyle; vmin::Float64; vmax::Float64; count::Int; end`
    `vmin`, `vmax` and `count` (cells that are not `NaN`) are kept up to date by every writer of the grid.
  - `const GRID_BLOCK_BYTES = 16 * 1024 * 1024`
  - `create_grid(folder, name, T, nx, ny; dx, dy, x0, y0, rotation = 0.0, crs = "", units = "")::Grid`: makes the folder, writes `grid.json` and sizes `values.f32` or `values.f64` to `nx * ny` values without writing them (the writer fills every cell).
  - `open_grid(folder)::Grid`: throws `GridError` when `grid.json` is missing or broken, or the value file has the wrong size.
  - `save_grid_meta(g)`: writes `grid.json` atomically.
  - `values_path(g)::String`
  - `block_rows(g)::Int`: rows per block, `max(1, GRID_BLOCK_BYTES ÷ (nx * sizeof(T)))`.
  - `read_rows(g, j1, n)::Matrix{T}` (size `nx` by `n`) and `write_rows!(g, j1, block)`: positioned file reads and writes, no map. `write_rows!` takes a `Matrix{T}` only.
  - `with_grid_values(f, g; write = false)`: maps the values as `Matrix{T}` of size `(nx, ny)`, calls `f(A)`, then syncs (when `write`) and unmaps with `finalize(A)` before it returns, also on error.
  - `cell_centre(g, i, j)::Tuple{Float64,Float64}`: ground position of cell `(i, j)`, with rotation.
  - `grid_corners(g)::NTuple{4,Tuple{Float64,Float64}}`: outer corners of the grid (cell edges, not centres), lower-left first, counter-clockwise.
  - `grid(p::Project, id)::Grid`: like `database(p, id)`; throws `ProjectError` for a missing folder or a non-grid item.
  - File layout: `values.*` holds row 1 first; within a row, `i` goes from 1 to `nx` (east when not rotated). So the map is a Julia `Matrix` of size `(nx, ny)` with `A[i, j]`.
  - `grid.json` holds every field of `Grid` except `folder`, plus `"version": 1`; `eltype` is saved as `"float32"` or `"float64"`.

### Task 3: GeoTIFF, ER Mapper and Surfer import through GDAL

**Files:**
- Create: `src/io/georef.jl`, `src/io/gdal_grid.jl`, `test/test_gdal_grid.jl`
- Modify: `JuliaMagCore/Project.toml` (add `ArchGDAL = "0.10"`), `src/crs/crs.jl`

**Interfaces:**
- Consumes: Tasks 1, 2.
- Produces:
  - `georef_from_affine(gt::NTuple{6,Float64}, nx, ny)::NamedTuple{(:dx, :dy, :x0, :y0, :rotation, :bottom_up)}`.
    `gt` is GDAL's `(gx, a, b, gy, c, d)`: ground `x = gx + col * a + row * b`, `y = gy + col * c + row * d`, for pixel corner `(col, row)` counted from the first stored row.
    `dx = hypot(a, c)`, `dy = hypot(b, d)`, `rotation = atan(c, a)` in degrees.
    `bottom_up` is true when the first stored row is the south row (`a * d - b * c > 0`).
    The centre of the lower-left cell is `x0, y0`.
    Throws `GridError("the grid is skewed ...")` when the columns of the matrix are not at right angles within `1e-9` relative.
  - `affine_from_grid(g)::NTuple{6,Float64}`: the inverse, for a top-down file (first row is the north row).
  - `crs_from_wkt(wkt)::String`: `"EPSG:n"` when Proj identifies it with confidence 100 (`proj_identify`), else the WKT, `""` for empty text.
  - `crs_wkt(code)::String`: WKT 1 (GDAL style) of a code, `""` for `""`.
  - `read_gdal_grid(s, path, settings, progress; format_name = "")::ImportResult`: opens the file read-only with GDAL, takes band `settings["band"]` (default 1), and reads blocks of rows with `ArchGDAL.read!` into the sink.
    Nodata becomes `NaN`. Band scale and offset are applied. `Byte`, `Int8`, `UInt16` and `Int16` bands become `Float32`; `Int32`, `UInt32` and `Float64` become `Float64`; `Float32` stays.
    The source records the GDAL driver's long name as `format`, the band type as `eltype`, and `COMPRESSION` metadata when present.
    A rotated file reads with its rotation. A multi-band file warns that only band `n` of `m` was read.
  - Importers `"import.geotiff"` (`.tif`, `.tiff`) and `"import.ers"` (`.ers`), both with one setting `NumberSetting("band", "Band"; default = 1, min = 1, integer = true)`.
  - GDAL errors are turned into `GridError` with GDAL's message; GDAL's own error printing is silenced (`ArchGDAL.GDAL.cplseterrorhandler` or a quiet handler, set once at `__init__`).

### Task 4: Geosoft `.grd` reader, uncompressed

The byte layout, dummies and orientation rules are in `docs/research/geosoft-grd-format.md` sections 1 to 3.
That file is the requirement for every number in this task; its tags say how each fact was checked.

**Files:**
- Create: `src/io/geosoft_grd.jl`, `test/test_geosoft_grd.jl`, `test/data/grids/` (public sample files and `LICENSE.md`)

**Interfaces:**
- Consumes: Tasks 1, 2.
- Produces:
  - `struct GrdHeader; es::Int; sf::Int; ne::Int; nv::Int; kx::Int; de::Float64; dv::Float64; x0::Float64; y0::Float64; rot::Float64; zbase::Float64; zmult::Float64; label::String; compressed::Bool; end`
  - `read_grd_header(io)::GrdHeader`: reads the 512 bytes little-endian (offsets in the research file, section 1). Throws `GridError` with a plain message for: a file shorter than 512 bytes; `ES mod 1024` not in 1, 2, 4, 8; a type that the table in section 1 does not list; `SF = 3` ("a colour grid holds colours, not values"); `KX` not `1` or `-1`; `NE` or `NV` below 1; `DE` or `DV` not above 0; `ZMULT == 0`.
    `IZMIN`, `IZMAX`, `IZMED`, `IZMEA`, `ZVAR` and `NVPTS` are ignored (they are unreliable in real files).
  - `grd_eltype(h)::DataType`: the stored element type from `ES` and `SF`.
  - `grd_dummy(T)`: the table in section 3. A value is a dummy when it equals the integer dummy, or for floats when it is `<= T(-1.0e32)` (compared in the stored type, before scaling).
  - `read_geosoft_grd(s, path, settings, progress; header = read_grd_header(...))::ImportResult`: for an uncompressed grid, reads exactly `ES * NE * NV` bytes after byte 512, in blocks of whole vectors, and puts them with `put_rows!` (`KX = 1`) or `put_columns!` (`KX = -1`).
    Real value is `stored / ZMULT + ZBASE`, done in `Float64` and stored in the grid's type (`Float32` for 8 and 16 bit and `Float32` files, `Float64` for 32-bit integer and `Float64` files).
    Georeference: `x0 = X0`, `y0 = Y0`, `rotation = ROT`; for `KX = 1` `dx = DE`, `dy = DV`; for `KX = -1` `dx = DV`, `dy = DE`.
    A file shorter than `512 + ES * NE * NV` bytes fails with `GridError("the file ends after <n> of <m> data bytes")`. Longer files are fine (blocking may pad them).
    The name defaults to the file name without `.grd`; `LABEL` goes into the report when it is not blank.
    The source records format `"Geosoft GRD"`, the element type such as `"int16"`, and compression `""`.
  - Compressed headers (`ES > 1024`) are handed to `read_geosoft_grd_compressed` of Task 5.

## Rulings made while writing this plan

These are my calls; each says what it costs if wrong.

- **Surfer grids go through GDAL**, not an own reader (spec 13.3 said own reader for Geosoft and Surfer). GDAL reads Surfer 6, 7 and ASCII well, so an own reader adds code and risk for nothing. Cost if wrong: one small reader later.
- **Grids store `Float32` or `Float64` only.** Integer files are converted on import. Cost if wrong: 2x the disk space of 16-bit grids, which are rare for magnetics.
- **ER Mapper export writes the Geosoft float dummy `-1.0e32`**, not `NaN`, so Oasis sees the dummies. GeoTIFF export writes `NaN`. Cost if wrong: a setting on the exporter.
- **Part B is in this plan** (Tasks 11 to 15) instead of plan 3, so plan 3 is UI only. Cost: plan 2 is longer.
- **Geosoft coordinate system: `.grd.xml` is read before `.grd.gi`**, and the writer writes `.grd.xml` only, never `.gi`. The `.xml` is plain, documented XML; `.gi` is an undocumented binary that was reverse-engineered. Cost if wrong: Oasis may show a written grid without a coordinate system until a `.gi` writer exists. This is the open check for the user in Task 7.
- **Only zlib-compressed Geosoft grids are read.** Every real compressed grid found was zlib. LZRW1 ("COMP=SPEED") gives a clear message. Cost if wrong: an LZRW1 decoder (about 80 lines) later.
- **Geosoft `.grd` export is uncompressed only**, as spec 7 says. The test helper can already write zlib blocks, so a compressed writer is a small step once Oasis has opened one. Cost: larger files than Oasis writes.
- **EzXML.jl reads `.grd.xml`**, rather than hand-made text matching, because the file holds old copies of the projection under `lineage`. Cost: one more binary dependency (libxml2).
- **No gridding tool yet.** The research suggested Direct gridding as an optional quick-look tool; it belongs with the gridding work after plan 5. Cost if wrong: one tool later.
