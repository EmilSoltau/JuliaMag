# JuliaMag Plan 1: Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A headless Julia package, `JuliaMagCore`, that holds a JuliaMag project, imports Geosoft XYZ and CSV line data fast and safely, exports line data, and runs tools and background jobs with undo and a script history.

**Architecture:** One package with no UI dependency.
Line databases are stored as one raw memory-mapped file per channel, with JSON metadata.
Every action goes through a `Session`, which records undo steps and history.
Tools, importers and exporters are plain data descriptions in registries.
The UI (plans 3 and 4) is built later on top of these registries.

**Tech Stack:** Julia 1.12, JSON3.jl, StructTypes.jl, Proj.jl, Parquet2.jl, Tables.jl, the Mmap and Test standard libraries, Aqua.jl and JET.jl for lint.

**Spec:** `docs/superpowers/specs/2026-10-28-juliamag-foundation-design.md` (sections 5, 6, 7, 8, 9.4, 9.5, 12, 13, 14).
UI reference: `prototype/juliamag-ui.html` (its JS tool descriptions show the intended shape of `ToolSpec`).

## The plans

| Plan | Delivers |
|---|---|
| **1. Core (this plan)** | Data model, storage, project, session and undo, tool registry, jobs, history, XYZ and CSV import, line export, first tools |
| 2. Grids | Grid item, Geosoft and Surfer `.grd`, `.ers`, GeoTIFF read and write |
| 3. UI shell | CImGui app, theme tokens, ribbon built from the registries, panes, backstage, command search |
| 4. Views | Map, database, profile and statistics views, import dialogs, linked cursor |
| 5. Packaging | Prebuilt app for Windows and Linux, loading tool packages while running |

## Global Constraints

- Julia 1.12 or newer.
- `JuliaMagCore` must not depend on any UI or graphics package (spec 13.3, "Code layout").
- A whole input file is never loaded into memory at once (spec 6.2).
- Bad input never throws out of an importer or tool to the caller; it becomes a warning with a line number, or a failed job (spec 6.2, 8.2).
- Float channels use `NaN` as the missing value; each integer type uses `typemin(T)`; strings use `""` (spec 5.3).
- XYZ missing value is the text `*` (spec 6.3).
- All paths inside a project are relative to the project folder (spec 5.1).
- Data is written at once; every change can be undone (spec 5.2).
- One sampling (fiducial start and step) per line (spec 5.3).
- Text in messages, comments and docs: plain English, short sentences, never the em dash character.
- Lint (Aqua, JET) and all tests pass before each commit.

## Review Focus

These inputs are not named by the spec but will reach real users first.
Each has a test in the task that owns the code.

1. **Windows files:** CRLF line endings and a UTF-8 byte order mark must import exactly like LF files (Task 6).
2. **Paths with spaces and brackets:** the user's own folders contain `(sh)` and spaces; projects there must create, open and move fine (Task 4).
3. **Cancel or failure part way through an import:** no half-made item is left in the project, and temp files are removed (Task 7).
4. **Rows with the wrong number of values:** the row is skipped with a warning naming the file line number; the import goes on (Task 6).
5. **A line number that appears twice in one XYZ file:** the second block becomes a new version of that line, not a merge or a crash (Task 6).

### Task 3: Column files and the line database

**Files:**
- Create: `src/storage/columns.jl`, `src/storage/database.jl`, `test/test_database.jl`

**Interfaces:**
- Consumes: Task 2 types.
- Produces:
  - Storage layout of a database folder:
    - `database.json`: name, description, lines (in order), channels, position pairs, `current_pair` index, `made_by` job id or `""`.
    - `channels/<name>.f64` (or `.f32`, `.i32`, `.i16`, `.i8`, `.u8`): raw little-endian values, all lines end to end; a line's rows are `offset+1 : offset+nrows`.
    - String channels: `channels/<name>.str` (bytes) plus `channels/<name>.off` (Int64 end offsets).
    - Array channels: values stored row-major, `arraylen` values per row.
  - `mutable struct LineDatabase; folder::String; name::String; description::String; lines::Vector{LineInfo}; channels::Vector{ChannelInfo}; pairs::Vector{PositionPair}; current_pair::Int; made_by::String; end`
  - `create_database(folder::String, name::String)::LineDatabase`
  - `open_database(folder::String)::LineDatabase` (throws `DatabaseError` with a clear message if `database.json` is missing or broken)
  - `save_meta(db::LineDatabase)` (writes `database.json` atomically: write `database.json.tmp`, then `mv` over)
  - `add_channel!(db, info::ChannelInfo)` (creates an empty column file sized to the current total rows, filled with the missing value)
  - `ColumnAppender` and `open_appenders(db, names)::Dict{String,ColumnAppender}`, `append_value!(a, x)`, `close_appenders!(d)`: buffered writes used by importers; buffer size 1 MiB per channel.
  - `add_line!(db, info::LineInfo)` (sets `offset` to the current total rows)
  - `read_channel(db, line::LineId, name::String)::AbstractVector` (a memory-mapped view; no copy)
  - `write_value!(db, line::LineId, name::String, row::Int, x)` returns the old value (used for cell edits and undo)
  - `write_channel!(db, line::LineId, name::String, values::AbstractVector)` returns the old values
  - `channel(db, name)::ChannelInfo`, `line(db, id)::LineInfo`, `total_rows(db)::Int`
  - `struct DatabaseError <: Exception; msg::String; end`

### Task 6: Chunked text reader and Geosoft XYZ import

**Files:**
- Create: `src/io/textscan.jl`, `src/io/registry.jl`, `src/io/xyz_import.jl`, `test/test_xyz.jl`
- Modify: `test/support/synthetic.jl`, `test/data/*.xyz` (small hand-written cases)

**Interfaces:**
- Consumes: Tasks 3 to 5.
- Produces:
  - `struct ImportWarning; file_line::Int; message::String; end`
  - `struct ImportResult; item::Union{Nothing,ProjectItem}; warnings::Vector{ImportWarning}; rows::Int; lines::Int; end`
  - `struct Progress; done::Function; cancelled::Function; end` with `report(p, fraction)` and `is_cancelled(p)::Bool`; `NO_PROGRESS` does nothing.
  - `eachfileline(f, path; chunk = 4 << 20)`: calls `f(lineno::Int, line::SubString{String}, bytes_read::Int)` for each line; strips a UTF-8 BOM and a trailing `\r`; reads in chunks.
  - `struct ImporterSpec; id::String; name::String; extensions::Vector{String}; kind::ItemKind; settings::Vector{SettingSpec}; run::Function; end` (`run(session, path, settings::Dict, progress)::ImportResult`); `SettingSpec` comes from Task 8, so declare `settings` as `Vector{Any}` here and tighten it in Task 8.
  - `register_importer!(spec)`, `importers()`, `importer_for(path)::Union{Nothing,ImporterSpec}`
  - `import_xyz(s::Session, path::String; name = basename-without-ext, crs = "", mode = :new, target = "", progress = NO_PROGRESS)::ImportResult`
    - `mode` is `:new` or `:append` (spec 6.5); with `:append`, `target` is the database item id; an existing line id gets the next free version.
  - Registered as importer `"import.geosoft_xyz"`, extensions `[".xyz"]`.
- XYZ rules (spec 6.3):
  - Channel names come from the last `/` comment line whose name count equals the column count of the first data row.
  - No such line: names are `C1, C2, ...` and one warning.
  - Line headers, case-insensitive: `Line`, `Tie`, `Base`, `Test`, `Trend`, `Random`, `Special`, and the one-letter forms `L`, `T`, `B`, `S`, `R`, `P`, `D` followed by a number; an optional `.v` version after the number.
  - `//Flight n` and `//Date yyyy/mm/dd` set flight and date for the lines that follow.
  - `*` is missing. Numbers parse with `tryparse(Float64, ...)`; a value that does not parse becomes missing with one warning per column per line (not per row).
  - A column named `FIDUCIAL` (any case) sets each line's `fid_start` from its first value and `fid_step` from the median difference; it stays a channel too.
  - Columns named `X`/`EASTING` and `Y`/`NORTHING` get roles x, y and form the first position pair with `crs`; `LON`/`LONG`/`LONGITUDE` and `LAT`/`LATITUDE` get roles and form a second pair with `"EPSG:4326"`.
  - Data before any line header goes into a line of type `RANDOM` number 0.
  - All channels import as `Float64`, protected (spec 5.3).
- Streaming: values go straight to `ColumnAppender`s; memory use must not grow with file size.
